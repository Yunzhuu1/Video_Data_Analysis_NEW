## [2026-08-13] MySQL 真实环境联调 + 端到端评测

**做了什么**：
- 用户本机安装 MySQL 8.0.46（Homebrew），配置 `root/123456` + `video_data_analysis` 库。
- 启动 Spring Boot（`SPRING_PROFILES_ACTIVE=dev`）：自动执行 `schema.sql` + `DataInitializer` 种子数据（7 指标 / 12764 事实事件 / 3713 播放明细 / 93 聚合行）。
- 启动 agent-engine（uvicorn:8090），新建 `agent-engine/.env`（`AI_API_KEY` 暂空）。
- 冒烟测试通过：Spring `/api/agent/analyze` → Python 引擎 → MySQL 真实 SQL 执行，全链路正常。
- 跑端到端评测 `--llm real --platform real`（21 条用例走真实平台）。

**Bug**：
- [BUG-001] `/internal/metrics` 返回 500：`MetricCatalogService.BASE_SQL` 的 SELECT 漏查 `fact_formula`/`fact_event_filter` 列，`map()` 读列时报 `Column 'fact_formula' not found`。→ 修复：SELECT 补上两列。（该 Bug 只有真连 MySQL 才会暴露，mock 模式跑不出来。）
- [BUG-002] eval runner `run_real_case` 两处：
  1. Spring 的 `debug.sqlRetryCount` 显式返回 `null` 时，`.get(key, default)` 不生效 → `int(None)` 崩溃，21/21 全 ERROR。
  2. Spring `/api/agent/analyze` 直接返回 `AnalysisReport`（无 `finalReport` 包装），runner 读报告字段全空。
  → 修复：`or 0` 兜底 + `or payload` 兜底。

**测试**：
- Python `pytest` 57/57、`ruff` clean、Java `mvn test` 14/14。
- 真实平台链路（fallback 模式，无 API key）：评测可用性 100%（21/21 无 ERROR）、端到端成功率 76.19%（16/21）、延迟 p50/p95 = 555ms/629ms。
- L1~L4 = 0%：无 API key 时语义解析不运行，属预期。

**结果**：
- MySQL 配置与真实平台链路完全验证通过；修复 2 个真实路径 Bug。
- 剩余 5 个失败均为无 API key 的预期行为：c15/c16/c17 依赖 mock 注入 guard/DQ 失败（仅 mock/replay 模式有意义）；c18/c19 需真实 LLM 生成高风险明细 SQL 才触发 HITL 审批。

**待办/下一步**：
- 在 `agent-engine/.env` 填入 DeepSeek `AI_API_KEY` 后重跑 `--llm real --platform real`，出真实 L1~L4 数字并验证 HITL/重试场景。
- 修复已提交到 `codex/eval-real-hotfix` 分支（含 `MetricCatalogService.java`、`runner.py`、`.gitignore`、`docs/开发日志.md`、`AGENTS.md` 日志规范）。
