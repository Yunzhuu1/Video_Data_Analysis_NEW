## [2026-08-17] memory-namespace-isolation 落地：eval 记忆自隔离

**做了什么**：
- 实现 change `memory-namespace-isolation`（分支 `codex/memory-namespace-isolation`）：
  - **MemoryStore namespace**：表加 namespace 列 + (namespace, norm_question) 唯一键 + 存量迁移（默认 default）。
  - **记忆控制 API**：POST /internal/memory/seed（**拒 default** + intent 校验）、POST /internal/memory/clear（幂等）、GET /internal/memory/entries（X-Internal-Token）。
  - **Java 透传链**：AgentController @RequestParam memoryNamespace → EngineAnalyzeRequest → LangGraphClient。
  - **graph state + 读/写钩子按 namespace**；**runner 无论 on/off 都用 per-eval namespace**（eval-<date>-<ts>）。
  - **毒化反例**：seed {问题文本 X, intent metrics 不一致} → 查询 X（相似度 1.0）→ metrics 一致性校验拦截。

**Bug**：
- [修复] runner --memory off 时 golden cases 仍写进服务器 default 记忆（写钩子在服务器端不受 runner 控制）→ 污染真实记忆 → 改为**始终用 eval namespace**（off 也隔离到 eval namespace，default 零污染）。
- [修复] SCHEMA/MemoryEntry 的 namespace 字段落盘遗漏（脚本中断）→ 补全。

**测试**：
- Java mvn test 52/52（memoryNamespace 透传断言）；Python pytest 84/84（store 隔离/控制 API/毒化反例）、ruff clean。
- **--memory on 全量自隔离（15:06）**：可用性 100%、**命中率 20%**、c24 重复对 PASS、**c25 毒化反例 PASS（hit=False，metrics 校验拦截）**、L1 100%、端到端 96%、**default 零污染**。
- **--memory off 回归（15:25）**：**L1/L2/L3 100%**（不回退）、端到端 96%（仅 c17 已知 mock 用例）、**default 零污染**。

**结果**：
- 两个跨进程限制根治：反例真预置（毒化变体测 metrics 校验路径）、eval 记忆自隔离（无需 env/重启/删库，default 永不被污染）。
- 已知特征（如实记录）：--memory off 时服务器记忆仍开启，golden 集内相同/相似问题（c15/c16、c02/c23）会产生**场内自命中**（命中率 16-20%），但 L1-L4 经 spec_score 校验、不回退，且隔离到 eval namespace 不污染 default——"off 命中率 0"在 real 模式需服务端显式关闭记忆（MEMORY_ENABLED=false）才字面达成。

**待办/下一步**：
- （可选）/analyze 增加 memoryEnabled 每请求开关，使 --memory off 字面命中率 0。
- 记忆系统向量检索演进（Retriever 接口已预留）。
- 分支 `codex/memory-namespace-isolation` 待 push + PR，之后 `/opsx:sync` + `/opsx:archive`。
