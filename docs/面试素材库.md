## 1. 项目定位（一句话）

构建了一个 **NL2DSL 的 ChatBI Agent**：用户自然语言 → LLM 语义解析为结构化意图（ResolvedIntent）→ **确定性合成器生成 SQL** → 统一门禁 → 执行 → 回答；配套语义记忆系统（命中直通/注入/表达映射）与**双闭环评测体系**（语义层 L1-L4 + 结果级 R1）。

## 2. 技术栈

Java 17 / Spring Boot 3（Spring AI）、Python 3 / LangGraph（StateGraph + checkpoint）、MySQL 8、DeepSeek（LLM）、火山方舟 doubao-embedding（2048 维）、LanceDB（HNSW cosine + ICU 中文 FTS）、OpenSpec 工作流。

## 3. 架构分层（面试必答）

**为什么 NL2DSL 而非 NL2SQL**：
- LLM 只输出结构化意图（intent/metrics/dimensions/time_range/filters/ordering），SQL 由确定性合成器产出
- 确定性：同意图同 SQL（可测可审计）；可控性：LLM 不接触 SQL 语法/表结构；可编排：记忆/门禁作用在意图层
- 长尾兜底：语义解析失败 → 降级 raw LLM SQL（fallback），但仍过门禁

**为什么 Java + Python 双栈**：
- Python（LangGraph）管编排（状态机/checkpoint/审批恢复）；Java（Spring）管平台治理（SQL 校验/执行/DQ/审计）
- 原则：**Python 不直连业务库**（执行必须走 Spring 统一安全入口）
- 解耦：LLM/编排演进不动平台层

**主链路**：ROUTER → SCHEMA → SEMANTIC_RESOLVE → SQL_SYNTHESIZE → SQL_HARD_GUARD → SQL_EXECUTE → SQL_SOFT_DQ → ANSWER；降级路径同样过门禁。

## 4. 底层设计问答（核心）

### 4.1 语义解析
- **LLM 怎么拿到指标名**：指标字典注入 prompt（Spring metric_catalog → build_semantic_user_prompt 渲染清单）+ system prompt 硬规则（只能用 metricCode）+ response_format=json 锁结构——**约束生成**，不是 LLM 自由发挥
- **怎么保证输出可靠**：`_acceptable_intent`（metrics 非空 + intent 合法 + confidence≥0.5）→ 不满足走降级
- **golden_spec 同构**：ResolvedIntent 与评测 golden_spec 同构 → 比较器直接逐字段比，无需转换

### 4.2 确定性合成器（synthesize）
- **同意图同 SQL**：纯函数（无副作用/IO），单测直接验证
- **_resolve_path 动态路由**：同一指标不同问法走不同表（聚合→metric_daily 预聚合；排名→fact 数事件）——语义层与物理存储解耦
- **多指标为什么难**：①跨源（不同指标不同表）；②fact 各指标 eventFilter 不同会空结果；③约束只允许全 metric_daily 列路径 + aggregate/trend，其余显式降级（宁可不做不做错）
- **SUM 包裹**：metric_daily 行粒度 (date,category)，group by 粒度不同才 SUM（防重复求和）
- **失败路径**：SynthesisError → 节点 catch → semantic_ok=False → 降级 raw SQL

### 4.3 门禁/安全
- **三态裁决**：PASS / RETRYABLE（反馈重写）/ APPROVAL_NEEDED（审批）
- **两阶段**：静态语义层（jsqlparser AST：表-列注册、敏感列、意图-形态一致）→ 计划层（EXPLAIN：FACT 全扫→审批）
- **审批不变式**：门禁只跑一次；审批通过后执行/DQ 失败**不再重生 SQL**（防审批对象漂移）——thread_id=run_id + checkpoint 恢复

### 4.4 评测体系
- **L1-L4**：核心/严格/平均/分项（golden_spec 逐字段）
- **FakeLLM**：录制回放离线回归
- **R1 结果级**：独立手工 SQL 取 seed 42 确定性真值 + **真实 MySQL 审计执行**系统合成 SQL——**防自我确认**（系统不能验证自己）
- **失败分类**：sql_error/exec_error/value_mismatch；交叉诊断只统计 value_mismatch（"解析对但 SQL 错"信号）
- **评测驱动修复闭环**：R1 抓 c03"最近7天无时间过滤"真实 bug → 修复 → R1 12/12→17/17 验证

### 4.5 记忆系统
- **记什么**：norm_question → ResolvedIntent（只存 intent 不存 SQL）；写门槛 = 全链路成功
- **读取三分支**：hit（直通复用 + metrics 一致性校验）→ hit_rejected（校验不过，防毒化）→ inject（few-shot 注入，intent 去重 top-3）→ miss（LLM）
- **防误命中**：hit_allowed 四重判定（band + catalog + metrics 一致 + 可接受）
- **namespace 隔离**：eval vs default，评测不污染真实记忆
- **表达映射**：别名表（aliases.yaml 最长匹配）+ 指纹（MetricIdFingerprint embedding 候选）
- **真实路径**：real-session 协议（首问沉淀→二问命中→持久化验证），8/8

### 4.6 相对时间
- time_expand：relative → absolute（含端点，锚点=数据末日，seed 42 确定性）
- 锚点同源：_resolve_path 后 source 的 timeField（防漂移）

## 6. STAR 故事（可整段讲）

- **STAR1 评测体系 + 驱动修复**：NL2DSL 缺可信评估 → golden_spec + L1-L4 + R1 → 端到端 47.6%→96%、R1 抓相对时间 bug 并修复
- **STAR2 语义记忆系统**：每问必调 LLM → 记忆命中直通/注入/表达映射 → 真实路径 8/8、token 省 21%、别名解锁
- **STAR3 产品能力补全**：多指标/相对时间缺失 → 同源多指标约束 + time_expand → n01 解锁、R1 12/12→17/17

## 7. 工程方法（体现素养）

- **渐进式变更**：20+ 独立 change（OpenSpec），每 change 独立分支 + 设计评审 + 评测回归 + 归档
- **评测驱动开发**：先建基线再开发；回归默认 --memory off（防记忆掩盖解析回归）
- **诚实方法论**：口径分离（场内自命中 vs 真实路径）、样本量卫生（N 标注）、防自我确认（R1 真值独立）、诚实报 0 增益
- **可复现**：seed 42 确定性 + 三变量标注（检索器/阈值/embedding）+ truth_source 审计

## 8. 演进点（面试加分：识别架构不成熟）

| 演进点 | 现状 | 为什么是演进点 |
|---|---|---|
| **schema linking（metric-recall）** | 全量 catalog（7→15 指标）进 prompt | 规模变大 prompt 变长 → L1 波动（实测：catalog 15 后既有用例单轮 93.9% vs 96.97%）→ 需要前置召回层（别名+embedding 缩小候选） |
| **数值过滤** | 合成器不支持 | 生产查询"完播率>50%"无法处理 → C2 |
| **跨源多指标** | n02 降级 | 不同源表指标合成 → C2 |
| **指标别名/指纹** | 部分落地 | 纯语义模糊（最受欢迎/热度）靠 LLM 兜底 → 指纹增强 |
