## 3. 安全（门禁 / HITL）

- **高风险拦截率 100%**（3/3 risk 用例全部 WAITING_APPROVAL）。
- **detail 意图确定性审批**：intent=detail → 无条件 APPROVAL_NEEDED（c18 稳定拦截，不依赖 LLM SQL 形态）。
- **自动放行补跑**：非 risk 用例被拦截后 runner 自动审批放行，端到端不误伤；意外拦截 0。
- **毒化反例**：seed「点赞量问题 + 播放量 intent」→ 查询同文本（相似度 1.0 进直通候选）→ metrics 一致性校验拦截（c25 PASS，hit=False）。

## 4. 效率（延迟 + token）

### 4.1 延迟（exp1：--memory on real+mock，25 条）
- p50 12.6s / p95 27.4s（模型 deepseek-v4-flash，temp=0）。
- 命中直通用例平均 10.6-14.3s（c23 10.7s 最快）。

### 4.2 Token（真实 LLM 调用，仅 runner 进程内可计量）
- 总消耗 66,117 token / 25 用例；**命中用例均值 2,160 vs 未命中 2,737（省 ~21%）**。
- 直通只消除**解析阶段** LLM 调用，AnswerAgent 仍调用 → **命中用例 token ≠ 0**（口径精确化）。

### 4.3 直通收益（重复对，N=1，见局限 §7）
| 指标 | 第一遍（未命中） | 第二遍（命中直通） | 差值 |

> 解读：命中后解析阶段 LLM 被跳过，但 **AnswerAgent 的生成 token/延迟方差（±数百/±数秒）大于被消除的解析阶段成本**，单样本无法可靠量化直通收益。正确测量需要**逐阶段计量**（语义解析 token 单独统计）或增大样本——这是本 change 最重要的方法论教训，已列入后续改进。

## 5. 记忆价值（直通 / 注入 / 冷热，按波段分层）

> **检索器配置三变量（2026-08-18）**：`hybrid(doubao-embedding-vision-251215)/hit=0.92-inject=0.82/w=0.7`
> 存储：LanceDB（HNSW cosine + ICU 中文 FTS）；embedding：火山方舟多模态端点（文本输入，2048 维）

### 5.0 阈值标定（真实 API，`calibrate_thresholds.py`，可复现）
| 对照组 | 融合分 | 判定 |
|---|---|---|
| 近重复（"统计各分类总播放量啊"） | **0.993** | ≥ hit_t → hit ✓ |
| 毒化（"点赞量" vs 播放量条目） | **0.867** | < hit_t + metrics_consistent 双保险 ✓ |
| 无关（"统计各分类总播放量" vs 播放量条目） | 0.655 | miss ✓ |
| 同义集 20 条 ≥ inject_t(0.82) | **85%**（17/20） | ≥60% 判据 ✓ |

|---|---:|---:|---:|---|

> 对比：eval-metrics 轮（difflib）N_inject=0（全 miss）→ 本 change **N_inject 0→8**——注入带首次可测量。

### 5.2 注入收益（组 A 无记忆 vs 组 B 有记忆，仅 inject 波段子集有归因意义）
**结果（exp2，真实 LLM + embedding）**：
- **N_inject=8**（s09-s13/s15/s16/s18，均为语义近义改写）；组 A（无记忆）L1=**100%**；注入子集 B L1=**100%**；**增益 0**。
- 诚实结论：本难度层的同义改写，LLM 无记忆已 100% 正确——**注入示例不改变 L1 结果**（预期内的测量结果，不再是"不可量化"）。
- 注入的价值测量从"空转"变为"可测的 0 增益"，且为后续"更难改写/冷门指标"的注入收益实验铺路。

**逐条审计**：`per_item` 含 a_intent/b_intent/golden/band 四列（JSON 已落盘），20 条可逐条核对。

### 5.3 冷热启动（检索侧：空记忆 vs seed 预置，消除写路径方差）
**结果（exp3，真实 LLM + embedding）**：
- 冷 L1=**100%** / 热 L1=**100%**（增益 0）；热命中 0/20；N_inject=8（与 exp2 一致，可复现）。
- 延迟 p50：冷 9.7s → 热 15.8s——**注入示例加长 prompt 使 LLM 生成变慢 ~6s**（这是 few-shot 注入的可量化成本，值得在报告注明）。

### 5.4 记忆价值总结（诚实口径）
| 维度 | 结果 | 归因 |
|---|---|---|
| 命中直通（token） | 命中用例均值 2,160 vs 未命中 2,737（**省 ~21%**） | eval-metrics exp1，N=4 命中 |
| 命中直通（单对，N=1） | token 差 -356 / 延迟差 -2,069ms | AnswerAgent 方差淹没解析阶段消除，需逐阶段计量 |
| 同问同答一致率 | 重复对 c24 PASS（第二遍 memory_hit=true） | semantic-memory 验收 |
| **注入带可测性** | **N_inject 0→8**（difflib→hybrid） | 混合检索（向量+BM25）使注入带可填充 |
| 注入 L1 增益 | 0（无记忆已 100%） | LLM 泛化强；注入价值在更难改写层待验证 |
| 冷热（检索侧） | 无 L1 差异；热延迟 +6s | 注入 prompt 成本可量化 |

**结论**：混合检索让注入实验从"空转"变"可测"；当前可量化价值 = hit 带确定性复用 + token 省 21% + 注入带可测量（N_inject=8）。注入对 L1 的增益为 0 是**诚实且可复现**的结论——为"更难改写/冷门指标"场景的注入收益实验提供了基线。

## 6. 实验协议与可复现

- **正交轴**：`--llm mock|record|replay|real` × `--platform mock|real`；token 计量仅 `real+mock`（图在 runner 进程内，meter 可归因）。
- **同义集**：`app/eval/synonym_cases.yaml`，20 条 = 5 类变换 × 4（指标/维度/时间/过滤排名/对比趋势），含 golden_spec + source_case；**不静态标 band**——band = 沉淀后对每条同义问题真实 `retriever.search` 取 top-1（运行时零偏差）。
- **重复命令**：
  ```bash
  cd agent-engine
  .venv/bin/python -m app.eval.runner --llm real --platform mock --memory on \
      --synonym-cases app/eval/synonym_cases.yaml          # 注入实验
  .venv/bin/python -m app.eval.runner --llm real --platform mock \
      --synonym-cases app/eval/synonym_cases.yaml --cold-hot  # 冷热实验
  ```
- **逐条审计**：同义集每条输出四列表（无记忆 intent / 有记忆 intent / golden / band），实验 JSON `per_item` 已含 `a_intent/b_intent/band`。
- **样本量卫生**：报告固定输出 N_hit/N_inject/N_miss；inject 子集 <8 显式标注「样本不足，结论仅方向性」。
- **回归隔离**：全量回归默认 `--memory off`，防记忆掩盖解析回归；记忆行为由 `--memory on` 专用用例覆盖。

## 7. 局限说明

1. **单用户 demo 环境**：本机 MySQL + 单一用户，无多租户/并发/生产流量。
2. **小样本**：N=20 同义集为方向性信号（±20pp 量级，~1.8σ 不构成强结论）；直通收益 N=1。
3. **token 计量**：仅 `real+mock` 模式可归因（图在 runner 进程内）；`real+real` 时 LLM 调用在服务器进程，runner meter 无数据（报告如 `tokens_total=None` 即此情形）。
4. **直通收益被 AnswerAgent 方差淹没**：用例总 token 差不能直接等价「解析阶段消除」，需逐阶段计量（后续改进）。
5. **同义集人工构造**：措辞由人重写，可能过拟合 golden 意图结构；逐条审计表用于暴露差异。
6. **band 阈值标定**：当前 0.95/0.85 为 difflib 经验值；向量检索上线时须按「已知相似反例全落在 hit 之下、期望注入同义条目全落在 inject 区间」方法重新标定（三变量配置随报告列出）。
7. **真实模式依赖 API usage 字段**：token 数字来自 DeepSeek 兼容 usage 响应，不同模型/供应商不可直接对比。
