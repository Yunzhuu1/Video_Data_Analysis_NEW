# 服务接口契约

> 本文档只描述当前真实实现的接口。审批路径以 `POST /api/agent/runs/{runId}/approval`（Java）与 `POST /runs/{runId}/approval`（Python）为准。

## 1. 约定

- 内部接口（`/internal/*`）仅供 Python Agent Engine 调用，通过 `X-Internal-Token` 共享 token 鉴权（当前实现为占位，鉴权 Filter 待补）。
- 所有 SQL 执行与校验必须经过 Spring Boot 统一入口，Python 不直连数据库。
- JSON 字段统一 camelCase。

## 2. Spring Boot 对外接口

### 2.1 发起分析（LangGraph 主线）

```http
GET /api/agent/analyze?userId=demo&message=分析各分类播放量趋势&nocache=true
```

响应（`AnalysisReport`）：

```json
{
  "runId": "run_20260611_001",
  "summary": "...",
  "period": "...",
  "metrics": [],
  "charts": [],
  "recommendations": [],
  "sql": "SELECT date, category, total_plays FROM metric_daily ...",
  "warnings": [],
  "dq": {}
}
```

`status=WAITING_APPROVAL` 时返回挂起报告（summary 说明审批原因）。

### 2.2 审批恢复

```http
POST /api/agent/runs/{runId}/approval
Content-Type: application/json

{"approved": true}
```

响应：`AnalysisReport`（审批通过后为执行结果报告；拒绝时 summary 说明已拒绝）。

### 2.3 运维接口

```http
GET  /api/agent/admin/tokens                # token/成本统计
GET  /api/agent/admin/recent                # 最近 20 条调用记录
GET  /api/agent/admin/runs?limit=20         # 最近运行列表
GET  /api/agent/admin/runs/{runId}          # 运行详情（含节点 trace）
POST /api/agent/admin/tokens/clear          # 清空 token 记录
POST /api/agent/admin/schema/refresh        # 手动刷新 schema 缓存
```

## 3. Spring Boot 内部接口（供 Agent Engine 调用）

### 3.1 SQL 硬校验

```http
POST /internal/sql/validate
Content-Type: application/json
```

请求：

```json
{
  "runId": "run_xxx",
  "userId": "demo",
  "question": "分析各分类播放量趋势",
  "sql": "SELECT date, category, total_plays FROM metric_daily",
  "purpose": "查询各分类每日播放量趋势",
  "allowHighRisk": false
}
```

响应：

```json
{
  "pass": true,
  "riskLevel": "LOW",
  "errorCode": null,
  "reason": null,
  "suggestion": null,
  "violations": [],
  "accessedTables": ["metric_daily"]
}
```

### 3.2 SQL 执行

```http
POST /internal/sql/execute
```

请求：同 `SqlExecuteRequest`（runId/userId/question/sql/purpose/allowHighRisk）。

响应（`SqlExecuteResult`）：

```json
{
  "success": true,
  "sql": "...",
  "columns": ["date", "category", "total_plays"],
  "rows": [],
  "rowCount": 31,
  "truncated": false,
  "warnings": [],
  "errorCode": null,
  "error": null,
  "riskLevel": "LOW",
  "accessedTables": ["metric_daily"],
  "durationMs": 23
}
```

### 3.3 SQL 结果 DQ 审核

```http
POST /internal/dq/sql-result/check
```

请求：`SqlDQCheckRequest`（runId/userId/question/queryResult）。

响应（`SqlDQCheckResult`）：

```json
{
  "pass": true,
  "riskLevel": "LOW",
  "reason": null,
  "suggestion": null,
  "warnings": []
}
```

### 3.4 指标字典

```http
GET /internal/metrics                  # 指标列表（?keyword= 可选）
GET /internal/metrics/{code}           # 按 code 查询指标定义
```

响应（`MetricDefinitionDto`）：

```json
{
  "metricCode": "total_plays",
  "metricName": "播放量",
  "businessDefinition": "播放事件总数",
  "formula": "total_plays",
  "sourceTable": "metric_daily",
  "timeField": "date",
  "factFormula": "COUNT(*)",
  "factEventFilter": "event_type = 'play'"
}
```

### 3.5 相关 Schema

```http
POST /internal/schema/relevant
Content-Type: application/json

{"question": "分析各分类播放量趋势"}
```

响应：

```json
{
  "schemaContext": "metric_daily: date,category,total_plays,...\n..."
}
```

### 3.5 Run Trace 回写

```http
POST   /internal/runs/{runId}/nodes          # 开始节点，返回 nodeId
PATCH  /internal/runs/{runId}/nodes/{nodeId} # 完成/失败节点
```

请求示例（开始节点）：

```json
{
  "nodeName": "SQL_GENERATE",
  "inputPayload": {"question": "...", "route": "complex"}
}
```

## 4. LangGraph Agent Engine 接口

### 4.1 健康检查

```http
GET /health
```

```json
{"status": "UP", "service": "agent-engine"}
```

### 4.2 执行分析

```http
POST /analyze
Content-Type: application/json

{
  "runId": "run_20260611_001",
  "userId": "demo",
  "question": "分析各分类播放量趋势",
  "bypassCache": false,
  "graphMode": "chatbi"
}
```

响应：

```json
{
  "runId": "run_20260611_001",
  "status": "SUCCESS | FAILED | WAITING_APPROVAL | REJECTED",
  "finalReport": {},
  "warnings": [],
  "approvalReason": null
}
```

### 4.3 审批恢复

```http
POST /runs/{runId}/approval
Content-Type: application/json

{"approved": true}
```

## 5. 超时建议

| 接口 | 超时 |
|---|---:|
| `/api/agent/analyze` 同步 | 90s |
| `/internal/sql/execute` | 30s |
| `/internal/schema/relevant` | 30s |
| LangGraph LLM 节点 | 60s |

## 6. 安全要求

- 内部接口必须鉴权（待补 Filter，占位 token：`dev-internal-token`）。
- SQL 请求必须记录 `userId` 与 `runId`。
- Agent Engine 不允许直接持有数据库账号。
- 不允许在 payload 中传 API Key。
