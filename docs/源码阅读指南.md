# 源码阅读指南（面试准备）

> 目标：不是"读完所有代码"，而是**读懂能让"为什么这么设计"讲清楚的类**。按面试被问概率分层。
> 阅读主线：**契约 → 链路 → 节点 → 合成 → 门禁 → 记忆**，串起"一次问答从问题到回答"的完整代码路径。

## 0. 阅读方法论（先读什么）

1. **先读契约**（state.py / dto）——理解"数据长什么样"，再读"怎么流转"。
2. **先读入口**（graph_builder / AgentController）——理解"主链路有哪些节点"，再深入每个节点。
3. **每读一个节点，想三个问题**：输入是什么？输出是什么？失败会怎样（降级/重试/拦截）？
4. **对照设计文档读**：`docs/ChatBI主链路开发设计.md`（讲"为什么"的权威来源）、`docs/记忆系统设计.md`。

---

## 1. 高效主线（6 个文件串起全链路）

按此顺序读，一次问答的完整路径就通了：

1. `agent-engine/app/graph/state.py` —— **契约**：ResolvedIntent 6 字段、DataAgentState、sql_source 取值
2. `agent-engine/app/graph/graph_builder.py` —— **链路**：节点顺序、条件边（降级）、记忆/checkpointer 注入
3. `agent-engine/app/graph/nodes.py` —— **节点实现**：语义解析/合成/门禁/执行/DQ/回答 + 记忆钩子 + 审批恢复
4. `agent-engine/app/synthesis/sql_synthesizer.py` —— **合成器**（最核心）：`_resolve_path` 动态路由、多指标约束、同意图同 SQL
5. `src/main/java/com/yunzhu/video_data_analysis/service/SqlGateService.java` —— **门禁**：三态裁决、AST+EXPLAIN 两阶段
6. `agent-engine/app/memory/retriever.py` —— **记忆核心**：混合检索、metrics_consistent 一致性校验、hit_allowed 四重判定

## 2. 必读清单（15 个文件）

### 架构骨架（2 个）

| 文件 | 答什么 | 重点看 |
|---|---|---|
| `agent-engine/app/graph/state.py` | 契约定义 | `ResolvedIntent` 6 字段；`DataAgentState` 全字段（resolved_intent/sql_source/memory_hit/memory_namespace/approval_status）；`sql_source` 的 Literal 取值 |
| `agent-engine/app/graph/graph_builder.py` | 主链路怎么搭 | `build_graph` 节点注册顺序；条件边（semantic 失败→SQL_GENERATE）；`init_graph`/`init_memory`/`run_chatbi_graph`；resume（审批恢复） |

### 语义解析 + 合成（3 个）

| 文件 | 答什么 | 重点看 |
|---|---|---|
| `agent-engine/app/agents/semantic_resolver.py` | LLM 只做语义匹配 + 确定性兜底 | `resolve()`（enabled 判断→prompt→normalize→fallback）；`_apply_fallbacks`（date 清洗/各分类补全/天粒度）；`_normalize` 输出契约 |
| `agent-engine/app/synthesis/sql_synthesizer.py` | 确定性合成 | `synthesize()` 入口校验（多指标约束）；`_resolve_path`（按 intent/dims 路由 metric_daily/play_detail/fact）；`_field_expr`（字段表达式 + JOIN）；SUM 包裹逻辑；absolute 时间 BETWEEN |
| `agent-engine/app/synthesis/time_expand.py` | 相对时间确定性展开 | `time_expand()`：含端点语义（最近 N 天 = 末日往前 N-1）、unit day/week、返回 `{type, absolute, granularity}` |

### 门禁/安全（2 个）

| 文件 | 答什么 | 重点看 |
|---|---|---|
| `src/.../service/SqlGateService.java` | 三态裁决 + 两阶段 | `verdict` 三态；静态语义层（AST）→ 计划层（EXPLAIN）；`APPROVAL_NEEDED` 触发条件（FULL_SCAN/LARGE_SCAN/DETAIL 无限制/敏感列） |
| `src/.../service/SqlStaticAnalyzer.java` | 不依赖业务库的静态校验 | jsqlparser AST 解析；表-列注册表（schema.sql）；敏感列判定；`SELECT *` 检测 |

### 评测（3 个）

| 文件 | 答什么 | 重点看 |
|---|---|---|
| `agent-engine/app/eval/runner.py` | 评测 harness 全貌 | `run_cases`（逐用例隔离/ERROR 不计分母）；正交轴（--llm × --platform）；记忆隔离（eval namespace）；`run_real_session`（真实路径）；`_check_case_result`（R1 MySQL 审计） |
| `agent-engine/app/eval/comparator.py` | L1-L4 四层评分 | `compare_spec`（归一化→分层评分）；core_ok/strict/avg_field/per_field |
| `agent-engine/app/eval/result_comparator.py` | R1 分层断言 | `check_result` 入口；exact/exact_per_key/trend_pattern/top_set 四类断言；`_check_series` 方向判定 |

### 记忆（4 个）

| 文件 | 答什么 | 重点看 |
|---|---|---|
| `agent-engine/app/memory/store.py` | 记忆记什么 | `MemoryEntry` 字段（norm_question/resolved_intent/metric_codes/resolver_hash/namespace）；upsert（namespace 唯一键）；`compute_resolver_hash`（prompt+resolver 内容哈希，规则变更自动失效） |
| `agent-engine/app/memory/retriever.py` | 防误命中 | `extract_metric_names`/`metrics_consistent`（问题文本匹配指标 vs 存储一致）；`hit_allowed` 四重判定（band+catalog+一致性+可接受）；HybridRetriever 融合分公式 |
| `agent-engine/app/memory/vector_store.py` | LanceDB 双后端 | 表结构（MemoryEntry + embedding）；upsert 时同步 embed（失败不持久化）；向量/FTS search 分开查；索引惰性建 |
| `agent-engine/app/memory/aliases.py` | 指标表达映射 | `load_aliases`（aliases.yaml → dict，长词优先=最长匹配）；`get_aliases` 单例缓存 |

### Java 入口（1 个）

| 文件 | 答什么 | 重点看 |

## 5. 读代码时的自检清单

读完每个核心模块，能回答：
- [ ] 这个设计解决什么问题？（为什么不用更简单/更重的方案）
- [ ] 失败路径是什么？（降级/重试/拦截/审批）
- [ ] 有没有防"系统骗自己"的机制？（如 R1 真值独立、评测记忆隔离、回归默认 off）
- [ ] 面试会追问什么？（清单见 `docs/简历素材.md` §5 面试问答防御）
