# 简历素材摘要（ChatBI Agent 项目）

> 生成：2026-08-19 | 所有数字可回溯至 `docs/metrics-report.md` / `docs/eval-reports/` / 开发日志。
> 主线定位：**NL2DSL（LLM 只做语义匹配 → 确定性合成 SQL）**，非 NL2SQL 直出——确定性、可审计、门禁可控。

## 1. 项目一句话定位

构建了一个 **NL2DSL 的 ChatBI Agent**：用户自然语言 → LLM 语义解析为结构化意图（ResolvedIntent）→ 确定性合成器生成 SQL → 统一门禁 → 执行 → 回答；配套**语义记忆系统**（命中直通/注入/别名表达映射）与**双闭环评测体系**（语义层 L1-L4 + 结果级 R1）。

## 2. 简历 bullet（可直接用）

1. **架构**：基于 LangGraph StateGraph 编排 ChatBI 主链路（语义解析 → 确定性 SQL 合成 → 硬门禁 → 执行 → DQ → 回答），LLM 只输出结构化意图不写 SQL，合成器保证同意图同 SQL；用 Spring Boot 统一安全网关（SQL 校验/执行/审批），Python 不直连业务库。
2. **评测体系（双闭环）**：自建 eval harness（golden_spec + 四层评分 + FakeLLM 录制回放 + mock/replay/real 三模式），45 条用例基线下 **L1 口径正确率 96-100%、高风险拦截 100%、端到端 47.6%→96%**（12 轮迭代收敛）；新增**结果级评测 R1（17/17=100%）**——用独立手工 SQL 采集确定性种子数据真值，再以真实 MySQL 独立执行系统合成 SQL 比对，形成"语义层 + 结果层"双闭环。
3. **评测驱动修复**：R1 上线即抓到"最近7天"相对时间无过滤的真实缺陷，驱动合成器语义修复并用 R1 验证（12/12→17/17）——评测不摆设，直接反哺系统。
4. **语义记忆系统**：沉淀"问题→ResolvedIntent"成功路径（SQLite + LanceDB 双后端），命中直通省 ~21% token、同问同答一致率 100%（真实路径 8/8）；混合检索（embedding 余弦 + BM25 融合）把注入带从不可测（0）拉到可测量（N_inject 0→8）；**指标表达映射**（别名表 + 自学习指纹）解锁 hard 层可判定缺口 13→3。
5. **产品能力**：多指标同查（"播放量+点赞量"）从降级 raw SQL 走向确定性合成；相对时间语义（"最近7天"）确定性展开。

## 4. 技术架构全景（面试主线条）

```
用户问题
  → LLM 语义解析（ResolvedIntent：指标/维度/时间/过滤/排序）── 记忆前置：命中直通 / 注入示例
  → 确定性合成器 synthesize（同意图同 SQL；多指标/相对时间）
  → SQL_HARD_GUARD（jsqlparser AST 静态语义 + EXPLAIN 计划层 → PASS/RETRYABLE/APPROVAL_NEEDED）
  → SQL 执行（Spring SQL 网关，Python 不直连库）
  → 软 DQ → 回答（AnalysisReport）
记忆系统：MemoryStore（SQLite/LanceDB）→ HybridRetriever（向量 cosine + BM25 融合）→ 别名/指纹表达映射
评测体系：golden_spec L1-L4（语义层）+ R1（结果级，独立 MySQL 审计）
```

## 5. 面试问答防御

| 追问 | 回答要点 |
|---|---|
| 为什么 NL2DSL 不直接 NL2SQL？ | LLM 只做语义匹配（可约束），SQL 由确定性合成器产出——同意图同 SQL、可审计、门禁可控；LLM 直出 SQL 漂移且绕过语义层 |
| R1 怎么防"系统自己验证自己"？ | 真值用**独立于合成器的手工 SQL** 采集（truth_source 记录），执行用**真实 MySQL 独立审计**，不消费系统输出 |
| 记忆注入为什么增益 0？ | 诚实：当前难度层 LLM 泛化饱和（难层 15/15、澄清收益 0 三线一致）；注入价值在更难样本待验证——不夸大 |
| 为什么选 LanceDB 不用 Milvus/Chroma？ | 嵌入式零服务、原生混合检索（HNSW 向量 + ICU 中文 FTS 一条通道）、按文件隔离；Milvus 重（分布式）、Chroma 无成熟混合检索 |
| 中文检索难点？ | 字符相似度对中文短句失效（实测注入带 0）；转 embedding + BM25 双信号融合 + 阈值标定（毒化/同义/近重复三组对照） |
| 多指标/相对时间为什么难？ | 多指标需同源同粒度（事实路径 factEventFilter 不同会空结果，显式降级）；相对时间需锚点（数据末日）确定性展开，R1 抓到过无过滤 bug |
| 审批 HITL 怎么做的？ | LangGraph interrupt + SQLite checkpoint 持久化，审批后同 SQL 续跑（门禁只跑一次，不二次拦截） |
| 评测可信度？ | 确定性种子数据（seed 42）+ FakeLLM 录制回放 + mock/replay/real 三模式 + 样本量卫生（N 标注、误差口径） |
| 项目规模？ | 20 个渐进 change（OpenSpec 工作流），每个独立分支 + review + 评测回归 |

## 7. 技术栈清单（简历技能栏）

- **后端**：Java 17 / Spring Boot 3（Spring AI）、Python 3 / LangGraph（StateGraph + checkpoint）、MySQL 8
- **LLM/Embedding**：DeepSeek（语义解析/回答）、火山方舟 doubao-embedding（2048 维）
- **向量/检索**：LanceDB（HNSW cosine + ICU 中文 FTS）、BM25 + 余弦混合融合（自实现）
- **评测**：自建 eval harness（golden_spec + L1-L4 + R1 结果级 + FakeLLM 录制回放 + mock/replay/real）
- **工程**：OpenSpec 变更工作流、Git 分支/PR review、pytest/ruff（Python）、mvn test（Java）、AI SDK 多厂商适配

## 8. 项目亮点 Top 3（最值得讲的三件事）

1. **NL2DSL 确定性架构**：LLM 只做语义匹配（输出结构化意图），SQL 由确定性合成器产出——同意图同 SQL、可审计、门禁可控；避免 NL2SQL 直出的漂移与不可控。
2. **双闭环评测 + 评测驱动修复**：语义层（L1-L4）+ 结果级（R1 真实执行数值）双闭环，且 R1 上线即抓到"最近7天无时间过滤"真实缺陷，驱动修复并验证（12/12→17/17）——评测不摆设，反哺系统。
3. **语义记忆系统**：从命中直通（省 token）→ 注入带可测量（0→8）→ 指标表达映射（别名+指纹，hard 缺口 13→3）的完整演进，真实路径命中率 8/8。

## 9. STAR 式成果故事（面试可整段讲）

**STAR 1：评测体系从零搭建 + 驱动真实修复**
- Situation：NL2DSL 链路缺可信评估，端到端初测仅 76%、LLM 直出 SQL 漂移严重。
- Task：建一套可复现、可回归、能抓真实 bug 的评测体系。
- Action：golden_spec 结构化标准答案 + L1-L4 四层评分；FakeLLM 录制回放 + mock/replay/real 三模式；新增 R1 结果级断言（独立手工 SQL 取 seed 42 确定性真值，真实 MySQL 审计执行，防自我确认）。
- Result：N=45 基线下 L1 96-100%、R1 17/17、端到端 47.6%→96%；R1 上线抓到相对时间无过滤缺陷并驱动修复闭环。

**STAR 2：语义记忆系统从命中直通到表达映射**
- Situation：每问必调 LLM（漂移+成本+无沉淀），真实命中率无数据。
- Action：MemoryStore 沉淀问题→ResolvedIntent；LanceDB 混合检索（向量+BM25）；别名表 + 自学习指纹表达映射；real-session 真实路径评测协议（首问沉淀→二问命中→持久化验证）。
- Result：真实路径命中率 8/8、token 省 ~21%、同问同答一致率 100%、别名解锁 hard 匹配缺口 13→3、注入带从 0 到可测量。

**STAR 3：多指标与相对时间产品能力补全（评测驱动）**
- Situation：多指标"播放量+点赞量"固定降级 raw SQL；"最近7天"合成 SQL 无时间过滤（R1 抓到）。
- Action：同源表多指标聚合（约束显式降级防空结果）；time_expand 相对时间确定性展开（数据末日锚点）。
- Result：n01 从 fallback→semantic、R1 12/12→17/17、L1 零回退——能力补全全部由评测数字验证。

## 10. 工程方法论（体现工程素养）

- **渐进式变更**：20 个独立 change（OpenSpec 工作流），每个 = 独立分支 + 设计评审 + 实现 + 评测回归 + 归档；main 始终可运行。
- **评测驱动开发**：先建评测基线（golden + R1）再开发；每个能力改动必须过 --memory off N=45 回归（防记忆掩盖解析回归）。
- **诚实方法论**：口径分离（场内自命中 vs 真实路径）、样本量卫生（N 标注/误差口径）、防自我确认（R1 真值独立于合成器）、诚实报告 0 增益（不夸大）。
- **可复现**：seed 42 确定性数据 + 三变量标注（检索器/阈值/embedding 模型）+ truth_source 审计。

## 6. 诚实边界（主动讲比被动问好）

- 单用户 demo 环境（无多租户/生产流量）
- 小样本（N=20 同义集为方向性；直通收益 N=1 方差大）
- token 计量仅 real+mock 模式可归因
